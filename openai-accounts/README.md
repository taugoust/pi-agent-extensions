# Native OpenAI accounts

`/accounts` manages named native OpenAI ChatGPT OAuth grants and API keys. Selection is recorded per Pi session; choosing **Restore default Pi login** restores Pi's complete built-in OpenAI authentication/configuration. The native Pi OAuth flow and existing OpenAI model registry are used; no Codex provider is registered and Codex account files are not migrated or activated. A separately registered custom native provider under `openai` is outside this phase: the extension refuses to install its gate and leaves that provider registration untouched.

The private store is `<getAgentDir()>/pi-accounts.json`. Credentials are stored with mode `0600`, atomic writes, symlink/path validation, and cross-process locking through vendored `proper-lockfile` 4.1.2 plus its declared runtime dependencies. Other provider sections in an existing store are preserved. Refresh uses the upstream serialized refresh/store path. Failed activation installs the fail-closed auth marker; requests do not fall back to Pi defaults or environment keys.

Credential management is restricted to native TUI mode. API-key entry is visibly labeled and unmasked; use a trusted terminal. Paseo receives only the versioned safe account-controls snapshot and can switch existing accounts while a session is idle; it never receives credential values and cannot add, remove, or log in to accounts. Switching makes no model call and does not compact or alter conversation context. Account selection revisions and lifetime epochs reject stale clients; exact request-ID retries replay their original result, while different intent under a reused ID is rejected.

A request-time OpenAI Responses provider-config `streamSimple` wrapper gates both ordinary provider dispatch and direct `ModelRegistry.streamSimple()` calls, including physical models routed from `idle-guard`. It activates and verifies auth immediately before calling the captured native provider; an `onPayload` recheck blocks requests if session, selection revision, activation ownership, or effective auth changed. It uses public ModelRegistry registration/auth methods for the gate; the activation coordinator retains a tested Pi 1.0.0 compatibility path to the private runtime's runtime-API-key setter because no public registry setter exists.

Enable with `programs.pi.extensions.accounts.enable = true;`. For the separate safe `/usage` credential-status command, also enable `programs.pi.extensions.usage.enable = true;`.
